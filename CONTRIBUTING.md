# Как се предлагат промени

Този проект е поддържан основно от един разработчик за нуждите на конкретно
читалище, но следва обичайните практики за отворен код, за да е лесно за
преглед, независимо кой прави промяната (човек или AI асистент).

## Преди да пипнете код

1. Прочетете [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — обяснява
   границите главен процес/renderer, картата на `handlers/*.js` и капана с
   реда на зареждане (TDZ), който лесно се пропуска при добавяне на нов
   модул.
2. За добавяне на нова таблица/поле — вижте съответните раздели в
   [`electron-app/README.md`](electron-app/README.md#как-да-добавя-нова-таблица).
3. Пуснете тестовете, за да видите текущото зелено състояние:
   ```bash
   cd electron-app
   npm install
   npm test
   ```

## Стил на кода

- Коментарите в кода са на български — проектът обслужва българска
  читалищна библиотека и целият домейн (Наредба № 3, КДБФ, дневник) е
  българска регулаторна материя, която не се превежда добре.
- Всеки IPC handler минава през помощната функция `run(fn)` — хваща грешки
  и връща `{ok:false, error}`, никога не хвърля към renderer-а.
- Нов домейн в `handlers/` следва модела:
  `module.exports = function registerXHandlers(ipcMain, deps) { ... }`.
- Без нови тежки зависимости, когато вградените възможности на Node/Electron
  стигат — тестовата рамка е вграденият `node:test`, XLSX импортът е с
  вградения `zlib`, а не пакет. Причина: всяка нова зависимост усложнява
  `npm run build`/подписването на инсталатора.

## Тестове

- `node:test`, файл на всеки `handlers/x.js` → `test/handlers-x.test.js`.
- Фалшив `ipcMain` (виж шаблона в `docs/ARCHITECTURE.md`) + истинска
  temp-база (`fs.mkdtempSync` + `db/schema.sql`) — не мокваме самия SQL.
- Нова функционалност без нов/обновен тест не се приема.
- CI (`.github/workflows/ci.yml`) пуска `npm test` при всеки push/PR,
  независимо от клона.

## Версии и commit-и

Версията е `major.minor.patch` в `electron-app/package.json`. Всяка
смислена промяна (нов домейн, поправка на бъг, ново поле) получава:

1. Bump на версията в `package.json` **и** `package-lock.json`.
2. Запис в `electron-app/CHANGELOG.md` — двуезичен (BG/EN), кратко описание
   какво се променя и защо, брой тестове преди/след.
3. Един commit, обхващащ точно тази промяна — не се смесват несвързани
   промени в един commit (напр. механично извличане на домейн от `main.js`
   и поправка на бъг вървят в отделни commit-и, дори ако са открити в едно
   и също разследване).

## Публикуване на нова версия

Вижте [„Автоматично publish чрез GitHub Actions“ в
`electron-app/README.md`](electron-app/README.md#автоматично-обновяване) —
push-ване на таг `vX.Y.Z` пуска `.github/workflows/release-electron.yml`,
което build-ва инсталатора и публикува GitHub Release автоматично.

## Мерджване в `main`

`main` е защитеният, публикуван клон — от него излиза автоматичното
обновяване на вече инсталираните програми. Промени се разработват в
отделен клон/PR и се мерджват само след преглед и зелени тестове.
